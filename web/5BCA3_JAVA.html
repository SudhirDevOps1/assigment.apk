What do you understand by AWT?

Page 1 of 3Question 4 · What AWT is

Abstract Window Toolkit

AWT (Abstract Window Toolkit) is Java's first graphical user interface library. It is shipped in the java.awt package and provides windows, buttons, text fields, menus, layout managers, images, fonts and event handling. It was designed for Java 1.0 so that one program could run on Windows, Linux and Macintosh.

The word abstract is the key. AWT does not draw a button itself; it asks the operating system to draw one. Each AWT component therefore owns a native peer — a real OS widget behind the Java object. This is why AWT components are called heavyweight: they carry the weight of a native window resource.

The class hierarchy starts at Component. Container extends it and can hold other components; Window, Panel and Frame extend Container. A Frame is a full window with a title bar, a Panel is a plain rectangular area used to group components, and a Canvas gives a drawing surface.

Page 2 of 3Question 4 · Layout and events

Layout Managers and Event Handling

AWT never uses fixed pixel positions; a layout manager decides where each child goes and recalculates the arrangement when the window is resized. That is what keeps one program usable on screens of different sizes.

Interaction uses the delegation event model introduced in JDK 1.1. An event source (a button) keeps a list of listeners; when the user clicks, the source creates an ActionEvent and calls actionPerformed on every registered listener. The program therefore writes one small class instead of subclassing the button.

Strengths and Limitations of AWT

The great strength of AWT is portability of behaviour: because the operating system draws the widget, a button looks and feels native on every platform, and keyboard navigation follows the platform's own rules. The price is that the same program can look different everywhere, and pixel-perfect design is impossible.

The heavier problems are technical. A native peer per component consumes OS resources, so thousands of components become slow. AWT offers only a basic set of widgets and no true transparency, no anti-aliased text, no look-and-feel switching and no light-weight components. Some features (such as applets) are now deprecated.

PointAWTSwing

Swing reuses the AWT event model and layout managers, so AWT knowledge is not wasted: JFrame is a Frame, JButton is a button, and an ActionListener works unchanged. AWT also still supplies fonts, colours, images, printing and the clipboard.

Conclusion

AWT is Java's original, native-peer GUI toolkit: components, containers, layout managers and a delegation event model. It made portable GUIs possible; Swing later replaced its widgets while keeping its ideas.

Page 1 of 3Question 5 · Inheritance in Java

What Inheritance Means

Inheritance is the mechanism by which one class acquires the fields and methods of another. The class that is reused is the superclass (parent), and the class that reuses it is the subclass (child). Java writes this with the keyword extends.

Inheritance gives three benefits. It removes duplicate code, because common data and behaviour are written once in the parent. It creates an is-a relationship, so a Student is a Person and can be used wherever a Person is expected. And it enables polymorphism: a parent reference can hold a child object, and the child's overridden method runs.

Java supports single inheritance of classes — one parent only — but a class may implement any number of interfaces. The keyword super calls the parent constructor or a parent method, and this refers to the current object.

Page 2 of 3Question 5 · The program

Program: Inheritance and Method Overriding

InheritanceDemo.java
class Person {
    String name;
    int age;

    Person(String n, int a) {          // parent constructor
        name = n;
        age = a;
    }

    void show() {
        System.out.println("Name   : " + name);
        System.out.println("Age    : " + age);
    }
}

class Student extends Person {         // inherits Person
    String course;
    int marks;

    Student(String n, int a, String c, int m) {
        super(n, a);                   // call parent constructor
        course = c;
        marks = m;
    }

    @Override
    void show() {                      // override parent method
        super.show();                  // reuse parent output
        System.out.println("Course : " + course);
        System.out.println("Marks  : " + marks);
    }
}

class InheritanceDemo {
    public static void main(String[] args) {
        Person p = new Person("Rahul", 20);
        Student s = new Student("Aman", 21, "BCA", 480);

        p.show();                      // parent version
        s.show();                      // Student version
    }
}

The constructor of Student calls super(n, a) first, so the inherited fields are initialised before the subclass fields. The annotation @Override asks the compiler to confirm that a parent method really is being replaced.

Inheritance is used whenever one thing is a special kind of another: a SavingsAccount is an Account, a Car is a Vehicle, a Manager is an Employee. The rule of thumb is simple — if the relationship cannot be spoken as "is-a", prefer composition (a field) instead of inheritance.

Conclusion

Inheritance lets a subclass reuse a superclass through extends, extend it with new fields, and refine its behaviour with overriding. One copy of the common code serves every subclass.

Page 1 of 3Question 6 · Applet life cycle

What an Applet Is

An applet is a small Java program that runs inside a host application — usually a web browser or the appletviewer tool. It does not have a main() method; the browser creates the object and calls a fixed sequence of methods. A class becomes an applet by extending java.applet.Applet.

The browser controls the life cycle through four methods. init() runs once, after the applet is loaded, and is used for one-time setup. start() runs after init and again every time the page becomes visible. stop() runs when the user leaves the page, and destroy() runs once before the applet is removed. paint(Graphics g) is called whenever the applet must be redrawn.

Page 2 of 3Question 6 · The program

Program: init(), start() and stop()

LifeCycleDemo.java
import java.applet.Applet;
import java.awt.Graphics;

public class LifeCycleDemo extends Applet {
    String message = "Applet created";
    int starts = 0;

    public void init() {                  // once, after loading
        message = "init(): applet loaded";
        setBackground(java.awt.Color.white);
    }

    public void start() {                 // each time it is shown
        starts++;
        message = "start(): shown " + starts + " time(s)";
        repaint();                        // ask for paint()
    }

    public void stop() {                  // page left / minimised
        System.out.println("stop(): paused");
    }

    public void destroy() {               // before removal
        System.out.println("destroy(): removed");
    }

    public void paint(Graphics g) {       // redraw the applet area
        g.drawString(message, 40, 60);
        g.drawString("init once, start/stop repeat", 40, 90);
    }
}

The applet is embedded in a page with the <applet code="LifeCycleDemo.class" width="350" height="150"></applet> tag (or run with appletviewer). The browser creates the object, then calls init, start and paint in that order.

On the first load the order is init → start → paint. If the user switches to another tab and comes back, only stop and then start run again, so the counter becomes 2. Closing the page finally calls destroy. This is why a clock or an animation is stopped in stop(): the applet may be invisible but still running.

MethodCalled whenTypical work
init()Once, after loadingRead parameters, create components

stop()Page hidden or leftPause the thread, release the screen
destroy()Before unloadFree resources
paint(Graphics g)Whenever redraw is neededDraw text, shapes and images

Note. Applets are legacy technology: the applet tag is obsolete, browser plug-ins no longer run them, and the API is deprecated since JDK 9. The life-cycle concept is still examinable and still useful, because servlets, Android activities and JavaFX applications use the same idea of separate setup, start, pause and teardown stages.

Conclusion

The browser drives an applet through init, start, stop and destroy. init prepares, start runs whenever the applet is visible, stop pauses it when it is not, and destroy releases it for good.
